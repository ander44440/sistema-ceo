| Pergunta | Resposta |
|----------|----------|
| **O que é?** | Consumo RO do LFC na entrada MRE quando COA + caso estão resolvidos/inequívocos. |
| **Por que existe?** | Fechar W3 / ADR-022 / CA-MRE-* após T05 deliberativo sem Reader. |
| **Para quem existe?** | `executarRotaDeliberativa` / `montarEntradaMre` (enriquecimento). |
| **Como medir sucesso?** | Suíte `consumoLfcMre.imp092.test.js` + regressão LFC + regressão MRE + `npm run build` × 3 PASS. |

## 1. Ponto exacto de integração

| Passo | Onde |
|-------|------|
| 1 | `montarEntradaMre` permanece a montagem base (Acervo, HFC-reparse, ops) — **sync**. |
| 2 | **`enriquecerEntradaMreComLfc`** (novo) corre **depois**, em `executarRotaDeliberativa`, com `LfcReader`. |
| 3 | `ia.js` garante `lfcReader` no `mreCtx` via `obterLfcRuntime` (já existente). |

```text
montarEntradaMre(ctx)
  → enriquecerEntradaMreComLfc(entrada, { reader, coaId, instrucao, casoId? })
       ├─ sem COA / sem reader / sem pedido de caso → no-op
       ├─ caso_ambiguo → mensagem de esclarecimento; zero factos LFC
       ├─ caso resolvido + activos → injectar [LFC activo]; LFC prevalece sobre reparse de caso
       └─ nunca Writer
```

## 5. Divergências

| Item | Nota |
|------|------|
| `montarEntradaMre` sync | Mantido; enriquecimento LFC é passo async separado (HTTP Reader). |
| Reparse HFC | Não removido do código; com LFC autorizado, entradas `[Facto do utilizador…]` são **removidas de `factosOficiais`** (autoridade = LFC); mensagem/fio HFC podem permanecer como prova. |
| Writer/Reader | **Inalterados** (zero diff de contrato). |
| P1-2 | **Inalterado**. |
| **COA entrada vs sessão (pós-diag T05)** | `executiveEngine` usava só `obterCoaAtivo()`; HFC/bucket podia ser outro `coaId` → LFC lido no COA errado. **Corrigido:** `coaId` da entrada conversacional prevalece quando diverge da sessão (ADR-022 A1/CM2). |
| **CM12 disciplina (pós-diag T05×3 UI)** | Com LFC activo + só lacuna genérica, MRE ainda fazia `solicitar_dados` e a disciplina wipeava. **Corrigido:** disciplina não aplica; parecer remapeado para `monitorar`+`aguardar`; `preferirSolicitarDados=false` com LFC. |
